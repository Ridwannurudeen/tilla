## Threat model (cross-merchant authz / pricing integrity)

| Threat | Defense | Test |
|---|---|---|
| Tier spoofing: buyer claims an agent id to get wholesale price | **INV-1: a tier discount applies at settle-record time ONLY if the settled payer wallet == the on-chain owner wallet of the presented ERC-8004 agent id** (read-only registry `eth_call` via `app/chain.py` patterns, time-boxed). Unverifiable/mismatched claim ⇒ base price is what the 402 demanded; there is nothing to refund because the discount was never granted. | `test_tier_claim_wrong_wallet_pays_base` |
| Cross-merchant IDOR on tier config | Tier writes ride the EXISTING owner seams only: `POST /api/stores/{slug}/pricing` (`_require_store_key` in `app/main.py`) / `dashboard._owned_store`. New read surfaces expose no other merchant's tiers, costs, or buyer lists. | `test_tier_config_idor_blocked` |
| Underpayment via stale/forged tier in the 402 | The dynamic price hook (`agentic.resolve_price`) resolves the tier from DB + verified identity at challenge time; the settle path re-derives it (`record_settlement`) — mismatch ⇒ order records at the price actually paid, never a delivered-below-floor state. Tier prices validated ≥ 0.01 USDT (M1 bounds). | `test_settle_price_rederived` |
| Buyer-identity probe as enumeration/DoS | Identity lookup is cached (per agent-id TTL), time-boxed (`RPC_TIMEOUT_REQUEST`), sema-capped (`chain` semaphore), and rate-limited on the quote endpoint (slowapi). RPC outage ⇒ base price (fail-to-base, never fail-open-to-discount). | `test_identity_rpc_outage_base_price` |
| Federation ingest = SSRF / poisoned feed | Peer list is operator-configured (env/DB, never user-submitted URLs); fetch with `trust_env=False`, no redirects, size cap, schema-validate against the versioned feed spec; peer content is DATA (rendered nowhere, re-escaped in any JSON echo); never proxied purchases — discovery links out only. | `test_federation_rejects_oversize_and_offschema` |
| Wholesale terms leak | Tier params never appear in public `feed.json`/`llms.txt` (M13 rule: feeds leak no `pay_to`; extend: feeds leak no tier table) — only an opt-in `wholesale: true` boolean flag. Quotes are per-request. | `test_feed_leaks_no_tiers` |

## Increments

### 16.1 — Wholesale tiers on `pricing_params` + verified quote (M)
Additive schema inside the existing JSON column — **no migration**:
`pricing_params.tiers = [{"buyer": "erc8004:<id>" | "any_agent", "price_micro": int}]`,
set via the existing `POST /api/stores/{slug}/pricing` (extend its Pydantic body;
strict validation: ≤20 tiers, price bounds, no duplicates). New read
`GET /s/{slug}/quote?agent_id=…` (public, rate-limited): returns
`{base_price, tier_price?, requires: settle-wallet == agent owner}` — the quote is
advisory; INV-1 governs. Identity verification helper `app/b2b.py::verify_agent_owner
(agent_id) -> wallet|None` using read-only registry call (reuse `chain._rpc` seams;
registry address = the ERC-8004 IdentityRegistry on X Layer already used by the
Tilla ASP — constant in `config.py`).

**Accept (binary):** claimed ONLY if: `test_pricing_accepts_tiers` +
validation-reject tests; `test_quote_returns_tier_for_verified_agent`
(respx/eth_call mocked); `test_tier_claim_wrong_wallet_pays_base`;
`test_feed_leaks_no_tiers`; full suite green; live smoke: a tier configured on a
real store and the quote endpoint returning it (curl output logged).

### 16.2 — Tiered agent buy end-to-end (M)
Wire the tier into the buy path: `agent_buy` accepts `agent_id` in the body
(`_agent_buy_body`); `resolve_price` (already per-request, Spike 8) returns the
tier price when `verify_agent_owner` matches a cached verification; settle path
(`record_settlement`) re-checks payer==owner and records `tier_applied` on the
order (`Order` JSON/event_log — no schema change; use `log_event`). MCP tool
`get_product` echoes the quote fields for a supplied `agent_id`.

**Accept:** claimed ONLY if an **arm's-length scripted agent purchase at a tier
price settles with a real tx hash** (second wallet registered as an ERC-8004
agent, labeled self-trade) — otherwise the increment is code-complete-unclaimed.
Tests: `test_settle_price_rederived`, `test_tier_buy_mismatched_payer_records_base`,
`test_mcp_quote_fields`, `test_identity_rpc_outage_base_price`.

### 16.3 — Open protocol spec v1 (documentation IS the deliverable) (S)
Versioned `docs/specs/tilla-protocol-v1.md` + frozen artifacts: pin
`docs/openapi.feed.yaml` + `docs/openapi.external-feeds.yaml` (both exist), the
agent-card shape (`/.well-known/agent-card.json`), the 402 challenge conventions
(exact, `eip155:196`, USDT0 asset, dynamic payTo), the MCP tool surface, and the
quote/tier extension from 16.1 — each with a `version:` field and a JSON Schema
where applicable. A conformance checklist another implementer can self-run
against their instance (curl-only).

**Accept:** spec file committed; a `tests/test_protocol_goldens.py` asserting the
LIVE Tilla surfaces validate against the frozen schemas (so the spec can't drift
from reality silently).

### 16.4 — Federation ingest (`/discovery` mirror-of-mirrors) up to the boundary (M)
`app/federation.py`: operator-configured peer base-URLs (`TILLA_FEDERATION_PEERS`,
default empty = feature dormant); a background loop (webhook-loop pattern,
`WEBHOOK_INTERVAL`-style knobs) fetches each peer's `/discovery/resources` +
per-store `feed.json`, schema-validates (16.3 schemas), caches rows in a new table
`federated_listings` (migration `0012_federation`, additive; renumber to next free
head at build — 0010 pending elsewhere, M15 takes 0011). `GET /discovery/resources`
gains `?include=federated` returning peer listings marked
`{"origin": "<peer>", "federated": true}` and linking OUT to the peer's own
checkout — **Tilla never proxies, quotes, or settles a peer's sale; zero
fund-moving code** (the M13 rule).

**Accept:** claimed ONLY if the loop ingests a schema-valid fixture peer (a second
local Tilla instance in the test harness counts as fixture, labeled as such) and:
`test_federation_rejects_oversize_and_offschema`, `test_federated_rows_labeled`,
`test_no_peer_checkout_proxy` (grep-assert no settle/verify call in
`federation.py`), migration up/down/up, dormant-by-default test (empty peers ⇒
zero network).

## Parking (honest)

- **EXTERNALLY-BLOCKED — real federation:** missing dependency = **a second
  independent operator running the protocol** (VISION §3 precondition). 16.4
  builds and tests the entire ingest against fixtures up to that boundary; no
  claim of a live federated network until a non-self peer exists (its URL is the
  artifact).
- **EXTERNALLY-BLOCKED — cross-instance reputation/ratings:** needs the same
  second operator + the XMTP/task-board runtime (M10's gated half).
- **USER-gated:** the 16.2 live tier settlement (funds), publishing
  tilla-protocol-v1 externally (announcement = user-owned distribution).
