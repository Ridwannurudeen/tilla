## 2. Absolute invariants (a violation = stop and fix before proceeding)

1. **Non-custodial by default.** Human checkout and per-store agent purchases settle **directly to the merchant's wallet** (`pay_to = merchant`, never Tilla). The only custodial surface is Phase-3 escrow — opt-in, clearly labeled, phase-gated, and **still with no automated fund-moving code** (funds move only by a verified user action).
2. **Fail-closed everything.** Every store (agent- or human-created) is content-screened before it goes live; ambiguous/unavailable → refuse, never permit. Missing key/creds → 503, never a permissive default.
3. **Evidence integrity.** Never invent a number or a settlement. A rail ships **flag-OFF** until a real funded settlement proves it live (that proof step is human-run and recorded in `docs/PROOF-onchain.md`). Simulated stays labeled simulated; testnet is never described as mainnet. Public numbers are generated by code, never typed.
4. **Security.** No XSS/injection/hardcoded secrets. Merchant-controlled strings: **`textContent` only in JS (never `innerHTML`/`insertAdjacentHTML` for merchant data), autoescaped in templates.** Validate at boundaries. Secrets live only in the VPS `.env`, never in the repo, logs, or output.
5. **The "49" SSTI canary.** Rendered store HTML must never contain the substring "49" — `tests/test_render.py:66` asserts `"49" not in html` when the payload is `{{7*7}}` (proving autoescape, not evaluation). Any text OR CSS you add to `themes/*.html` / `themes/_checkout.html` must avoid the substring "49" (watch px/hex values, e.g. `#494949`, `49px`).
6. **No attribution, ever.** No Claude/Anthropic/AI mention in code, comments, commits, or PRs. **Never** add `Co-Authored-By`.

## 3. Quality Gate — must pass before EVERY commit

- **`python -m pytest -q` green.** Currently 1017 tests. Keep it green. Add tests for every new capability. For a bug fix: write the failing test first, then make it pass. (Suite takes ~2 min — allow for it.)
- **`ruff check .` clean AND `ruff format --check .` clean**, using the **pinned `ruff==0.15.22`** (CI installs it via `pip install -e ".[dev]"`; other ruff versions format differently and will red the CI). Same for `sdk/python`. If you formatted with a different local version, re-verify what CI sees: `git show HEAD:<file> | python -m ruff format --check -`.
- **Any inline `<script>` you touch:** extract it and run `node --check`.
- **Any theme/checkout/dashboard change:** render it (`app.render.render(content, addr, slug, theme)` for stores, `render.render_shell("_dashboard.html")` for the dashboard), then confirm the rendered output has **0** `innerHTML` for merchant data and **0** occurrences of "49".
- CI = two GitHub Actions jobs (`test` + `sdk-test`), each: `ruff check` → `ruff format --check` → `pytest -q`. Both must be green. Python **3.12**.

## 4. Codebase conventions (match; do not reinvent)

- **Read before write.** Read the target file in full and enough neighbors to match its naming, patterns, error-handling, and abstraction level. Grep for prior art before building — much is already there.
- **Stack:** FastAPI + SQLAlchemy + Alembic + Jinja2 (autoescape on) + slowapi. Merchant data is untrusted at every boundary.
- **Migrations:** additive only. **Chain off the CURRENT head** — today `0010_self_serve_create_store`, so the next is `0011` with `down_revision = "0010_self_serve_create_store"` (never an older head — that branches history into two heads). **Never batch-rebuild the `orders` table** (a rebuild reconstructs the M3 partial unique index `ux_orders_active_amount`; use plain `op.add_column`). Round-trip test every migration (up → down → up) and re-assert the partial index.
- **Theme fingerprints must survive:** `bold.html` keeps `class="stamp mono"`, `editorial.html` keeps `class="folio mono"` (asserted in `tests/test_api.py`).
- **Formatter trap (this bit repeatedly):** ruff/isort strips a just-added import that is unused *at edit time*. Add the import in the **same** change as its first use, or the runtime will `NameError`.
- **Git hygiene:** stage by **explicit path** (never `git add -A` — it has swept local-only files into commits). Small, logical commits, no attribution. Do not push to `main` or deploy without the human.
- **Dormant-rail discipline:** ships flag-off; flag flips only in the VPS `.env`, by the human, after a live proof. Before enabling logic, add a read-only capability probe (e.g. facilitator `/supported`) — the pattern already used for `AGGR_DEFERRED`.
- **Machine surfaces are the moat:** whenever you add a human capability, add the agent-equivalent (`feed.json` / per-store + root MCP / agent card), and make every purchasable action self-describe with a JSON-Schema requirement + an SLA.
